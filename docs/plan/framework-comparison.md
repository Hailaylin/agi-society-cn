# 框架技术选型交叉分析

> 调研日期：2026-05-10 | 更新：2026-05-10
> 分析对象：Astro、Nólëbase (VitePress)、Quartz
> **需求优先级：页面呈现效果（美观度） > 关系图谱功能**
> **关键区分：首页是呈现性页面（非内容性），wiki 是内容性页面**

---

## 0. 架构决策

```
agi-society.cn
├── 首页 (homepage/)  → 呈现性页面：品牌展示、视觉冲击、导航引导
│   最终方案：Astro        ← 59k Stars，Islands 架构，零 JS 默认
│   过渡方案：Nólëbase     ← 先用 VitePress 快速上线，后续替换
│
└── 知识库 (wiki/)    → 内容性页面：深度阅读、知识网络、图谱探索
    最终方案：Quartz v4.5.2 ← 12k Stars，力导向图谱，数字花园
```

**核心判断**：首页和 wiki 是两种截然不同的产物。首页追求呈现性（视觉设计驱动），wiki 追求内容性（信息架构驱动）。用同一个框架去兼顾两者必然有妥协。

---

## 1. 首页方案：Astro（最终）+ Nólëbase（过渡）

### 1.1 为什么首页不用传统"文档框架"

文档框架（MkDocs、VitePress、Quartz）的强项是**把 Markdown 变成可导航的文档站**。但首页不是文档——首页是**品牌的视觉陈述**，需要：

- 精心设计的 Hero 区域（大图/动画/标语）
- 自由布局（不局限于单列文档流）
- 动画与交互（滚动视差、渐显、粒子效果）
- 高性能（Lighthouse 满分是底线）
- 多媒体整合（视频背景、3D 场景、数据可视化）

这些都是文档框架的弱项，是 Astro 的强项。

### 1.2 Astro — 呈现性首页最佳框架

| 属性 | 详情 |
|------|------|
| **仓库** | [withastro/astro](https://github.com/withastro/astro) |
| **GitHub Stars** | 59,143 |
| **定位** | 内容驱动网站的 Web 框架 |
| **核心特色** | Islands 架构 — 零 JS 默认，按需水合 |
| **UI 框架** | React / Vue / Svelte / Preact / Solid 任意组合 |
| **许可证** | MIT |

**Astro 的呈现性优势**：

```
Islands 架构：
  ├── 静态 HTML 优先 → 页面秒开，Lighthouse 满分
  ├── 交互组件按需水合 → 动画/图表只在需要时加载 JS
  └── 零运行时开销 → 比 SPA 框架体积极小

页面设计自由度：
  ├── 完全自由的布局（非文档流约束）
  ├── 任意 UI 框架组件（React/Vue/Svelte 混用）
  ├── CSS 方案自由（Tailwind/UnoCSS/SCSS/纯 CSS）
  ├── 内置图片优化（自动转换 WebP/AVIF、响应式 srcset）
  ├── MDX 支持（Markdown + JSX 混合）
  └── Content Collections（类型安全的 Markdown 管理）

性能：
  ├── 默认零 JS 输出
  ├── 构建时渲染，无客户端 hydration
  ├── 图片自动优化（压缩、格式转换、懒加载）
  └── View Transitions API 原生支持（页面切换动画）
```

**Astro vs 文档框架（首页场景）**：

| 首页需求 | Astro | MkDocs Material | Quartz |
|------|:---:|:---:|:---:|
| 自由布局 | ⭐⭐⭐⭐⭐ | ⭐⭐ | ⭐⭐ |
| 动画/交互 | ⭐⭐⭐⭐⭐ | ⭐ | ⭐ |
| 性能 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 图片优化 | ⭐⭐⭐⭐⭐ (自动) | ⭐⭐⭐ | ⭐⭐⭐ |
| 开发效率 | ⭐⭐⭐ (需前端) | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ |
| 视觉冲击力 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ | ⭐⭐⭐ |

### 1.3 Nólëbase — 过渡期首页承载方案

在 Astro 首页开发完成之前，可用 Nólëbase 先行承载官网首页。

**为什么选 Nólëbase 做过渡**：

- 基于 VitePress，能快速将现有 Markdown 内容发布为网站
- 比 MkDocs 更灵活（Vue 组件可嵌入页面增强呈现效果）
- 双向链接 + 悬浮预览保留了一定的探索性
- 与 Quartz wiki 共享 Node.js 生态，部署配置统一

**过渡方案的局限**（也正是为什么最终要迁移到 Astro）：

- VitePress 本质上还是文档站框架，布局受限于文档流
- 没有 Hero 区域、卡片网格、动画等呈现性组件（需自己用 Vue 写）
- 视觉冲击力上限受限于 VitePress 主题框架

```
过渡策略：
  Phase 1: Nólëbase 快速上线 → 有官网，能看，能用
  Phase 2: Astro 精雕首页 → 品牌呈现质的飞跃
  Phase 3: Astro 首页 + Quartz wiki → 最终目标架构
```

## 2. 知识库方案：Quartz（不变）

### 2.1 为什么 Wiki 不是 Astro

Astro 可以做内容站，但它不是为"知识网络"场景设计的：

- Astro 没有知识图谱、反向链接、悬浮预览等原语
- 这些功能需要从零开发（Quartz 已经做好了）
- Astro 的强项是呈现性页面，不是知识点之间的关联导航

**结论**：Quartz 在知识库场景的地位不变。Wisdom of the crowd — 12k Stars，3700+ Fork 的数字花园框架，知识网络就是它的本职工作。

### 2.2 Quartz 当前状态

`wiki/` 目录已是 Quartz v4.5.2 项目，`wiki/content/` 已含迁移后的 Markdown 内容。

## 5. 分阶段实施计划

### Phase 1：过渡期上线（Nólëbase 首页 + Quartz Wiki）

| 任务 | 位置 | 优先级 |
|------|------|:---:|
| 搭建 Nólëbase 项目 | `homepage/` | P0 |
| 配置首页导航结构（精简，导向 Quartz wiki） | Nólëbase config | P0 |
| 统一两站视觉（配色、字体） | 全局 CSS | P0 |
| Quartz wiki 内容补全 | `wiki/content/` | P0 |
| 部署 Nólëbase 首页 + Quartz wiki | CI/CD | P1 |

### Phase 2：首页升级（Nólëbase → Astro）

| 任务 | 位置 | 优先级 |
|------|------|:---:|
| 首页视觉设计（Hero、卡片、动画） | 设计稿 | P1 |
| Astro 项目初始化 + 组件开发 | `homepage/` 重写 | P1 |
| 性能优化（Lighthouse 100） | Astro build | P2 |
| 替换 Nólëbase 首页 | 部署切换 | P2 |

### Phase 3：持续迭代

| 任务 | 位置 | 优先级 |
|------|------|:---:|
| 首页动画增强（滚动视差、微交互） | Astro 组件 | P3 |
| Wiki 图谱参数调优 | `quartz.layout.ts` | P3 |
| 监控和 SEO 优化 | 全局 | P3 |

## 6. 推荐决策总结

| 决策 | 方案 | 理由 |
|------|------|------|
| 首页最终框架 | **Astro** | 呈现性页面需要自由布局+动画+极致性能，文档框架做不到 |
| 首页过渡方案 | **Nólëbase** | 快速上线，Node.js 生态与 Quartz 统一，后续替换成本低 |
| 知识库框架 | **Quartz** | 知识网络唯一成熟方案，已就位于 `wiki/` |
| 原 MkDocs 站 | **退役** | 内容迁移后下线，保留为历史存档 |
